# BROK 提示词模板（豆包专家模式专用）

## 什么时候用

`web_search` 找不到、找不全、或返回的全是营销稿时，按这个模板生成提示词，让用户拿去豆包专家模式搜。豆包擅长中文垂直信息（实习招聘、付费课口碑、国内课程定价、本地化案例），是 web_search 的补充。

## 四要素必须齐

写完后自检：B / R / O / K 四段缺一不可。缺哪段豆包就在哪段瞎编。

### B - Background（用户处境）

把用户的真实情境写成 3 到 5 行事实陈述。包含：

- 身份（学校 / 年级 / 专业 / 现状）
- 时间点（什么时间想做什么）
- 关键约束（钱、时间、能力、人际等硬约束）
- 决策类型（选 A 还是 B / 做不做 X / 何时做 X）

不要写情绪。不要写「我很纠结」。豆包不需要知道用户有多焦虑。

### R - Role（让豆包扮演什么专家）

按场景选：

| 决策类型 | 让豆包扮演 |
|---|---|
| 实习 / 求职 | 资深 AI 行业招聘 HR / 校招导师 |
| 付费课 / 社群 | 知识付费行业研究员 / 课程测评博主 |
| 学习方向 | 该领域从业 5 年以上的工程师 |
| 关系处理 | 心理咨询师（不是情感博主） |
| 创业 / 副业 | 早期项目投资分析师 |

不要让豆包扮演「全知专家」，越宽越编。

### O - Objective（要它产出什么）

具体到字段。例：

- 「列出 5 个类似情境的真实案例，每个含：时间、当事人背景、决策、结果」
- 「给出 2026 年 X 行业 Y 岗位的薪资 P25 / P50 / P75 数据，注明来源」
- 「找 3 个负面案例（这条路走崩的人），分析崩在哪一步」

不要写「帮我分析一下」「给点建议」——豆包会还你 800 字鸡汤。

### K - Key Result（成功标准）

让豆包知道什么样的答案算合格。包含：

- 数据来源至少 N 个（例：3 个独立信息源，注明每条来自哪里）
- 时间限定（例：只看 2025 年后的数据 / 案例发生在最近 18 个月）
- 必须给反例（例：至少 1 条与主流叙事相反的证据）
- 不要观点，只要事实和数据

## 完整范例

场景：用户大一在纠结要不要花 499 买某 AI 社群。

```
# Background
我是***REMOVED***计算机大一学生（2026 级），跨专业，已学 C 语言、用 Claude Code 做 AI 工作流。
2026-06 在评估一个 499 元的 AI 社群（讲师做 AI 应用培训，目标用户偏成人 / 创业者）。
我有以下硬约束：年生活费有限，已交过一次 ***REMOVED*** 元课的钱拿到的产出有限，再花钱前想看清楚这次是否会重复。

# Role
请扮演一位做过 3 年以上知识付费行业研究的测评博主，重点观察过 2024 到 2026 年国内 AI 类付费课和社群的真实交付情况。

# Objective
帮我搜集以下信息：
1. 这位讲师过去 18 个月内做过的付费课 / 社群项目（项目名、定价、人数、主菜兑现率、赠品兑现率），列成表
2. 该社群目标用户画像（年龄段、职业、付费能力），明确说大一学生是否在内
3. 3 个真实购买用户的复盘（正面 1 个 + 负面 2 个，每个含购买时间、付了多少、3 个月后用上什么、是否续费）
4. 同价位（300 到 600 元）的同类 AI 社群对比 2 个，给替代方案

# Key Result
- 每条信息必须注明独立来源（小红书 / 知乎 / 公众号 / 朋友圈截图 / 直接对接的用户），不要拿讲师自己发的素材
- 负面案例至少 1 条，不要全是正面
- 时间限定在 2025 年 1 月之后
- 如果某条信息搜不到，明说「搜不到」，不要编
- 最后给一句结论：以学生身份购买的风险等级（高 / 中 / 低），附理由
```

## 拿到豆包结果后

用户粘回来时，按下面快速过一遍再用：

- 来源能不能点开？点不开的当无效
- 「3 个真实用户」是不是 3 个名字都没有的虚构对象？是 → 当 0 个用
- 负面案例有没有给？没给 → 让用户补搜一次「[讲师名] 退款 / 不值 / 失望」
- 数据时间是不是 2025 年后？老数据按权重打 0.5

过完关再进入步骤 4（内部视角微调）。
